# Everstate Knowledge Base — implementation report

## What was built and why

This is one TypeScript application, SQLite database and small browser interface. It combines the useful mechanisms from two earlier prototypes while retiring their folders from the active tree. The assignment, source CSV and original Git history remain visible. Logical services are folders rather than network services: a reviewer can follow `api.ts → application.ts → crawler/search/answer/measurements` without learning a framework. Agents, skills and prompts are actual runtime files. Coding agents assisted research, implementation and review; ongoing collection uses the same application code and provider APIs, not a coding-agent dependency.

The interface stays communicative while a request runs: elapsed time, actual searches, discovered passages, repeated-source counts and verification events arrive over SSE. The final answer has numbered links to right-side source cards, exact excerpts, publication/update/checked dates, and timed video links. Trust is a component score, not model confidence or a probability of truth. Costs and evaluation have separate screens; navigating saved results makes no paid model calls. The demo serializes expensive requests to keep its behavior and budget understandable. The answer renders above the research log, which collapses once the answer arrives; the log lists one line per page read, and full passages appear only in the cited source cards. Stopping a question, or closing the tab, aborts the in-flight provider call on the server, records the attempt as cancelled and frees the worker for the next question.

## Corpus and temporal evidence

The frozen corpus contains 939 documents: 935 web documents and four accepted video transcripts. It was expanded from the supplied URLs through configured site links and sitemaps, including documentation and external coverage. The [corpus report](docs/CORPUS.md) contains the actual discovery/fetch/exclusion counts and host-level gaps. Robots are checked before downloads and again on redirects; private-network destinations and cross-origin redirects are refused. The latter is intentionally conservative: some legacy redirects remain exclusions, while their configured current-domain sources are collected separately. HTML/Markdown extraction preserves headings, tables, nearby conditions and decimal quantities. Unsupported formats, network failures and missing dates remain explicit.

Publication, update and fetch dates have different meanings. A move to a new domain or a new HTTP Last-Modified header does not create a new publication date. A checked page supports an observation about what it said when checked; it does not establish when a role or price became effective. The agent compares authority and fact scope, preserving unresolved contradictions instead of taking a majority vote. For example, current active-network counts differ from cumulative historically supported counts; treating those as one metric would produce a plausible but misleading answer. These are general rules, not company-role lookup tables.

Six content groups contain duplicate/near-duplicate material. There are 927 canonical groups: seven redundant exact copies and five additional members of a six-document near-duplicate group account for the difference from 939 documents. Exact copies share one indexed representative. Every near-duplicate member remains searchable because a changed name or condition can be the important fact; grouping only limits repeated influence. The final index has 7,694 active chunks. Old revisions remain stored for audit, although the current search tools primarily query the active snapshot rather than a full revision-history interface.

Video was included because interviews supply historical context missing from product pages. The 186-candidate inventory distinguishes company participation from lookalike names and low-authority commentary. Six selected videos totaling 2.741 hours went through Soniox and one Gemini identity/role/consistency review each. Four produced usable attributed transcripts; two were quarantined. Official tutorials and first-party guest statements can have stronger authority than third-party commentary, but interviewer questions do not become company facts. Speaker roles belong to the recording context; upload date is not assumed to be recording date. Remaining candidate processing is explicitly pending, not silently counted as corpus coverage.

## Answering and safety boundaries

Search combines SQLite full-text retrieval and embedding rank fusion, then limits repeated content groups. The agent has bounded search, registered-document read, arithmetic and final-answer actions. Source data never grants access to arbitrary URLs, files, credentials or shell execution. The arithmetic parser accepts only numbers, parentheses and four operators, returns intermediate steps and checks inputs against evidence or explicit user scenarios. There is no executable expression evaluation and no CEO-specific route.

A draft answer is not verified against its own citations alone. For every claim the corpus is searched again for passages of equal or higher authority dated after the claim, and, when the wording is absolute (always, every, must, only), for exceptions and optional paths. Those passages are handed to the support review per claim, and where the corpus actually supplied such material the answer model runs one focused comparison per claim: a present-tense statement that a newer page supersedes fails a dedicated `currentness` check, and an absolute statement limited by a retrieved exception fails a `scope` check. The model must then cite the newer or limiting page and date or qualify the older statement. The first measured run after adding the general review still approved a 2025 announcement as the current chief executive; the focused comparison was added because one small model reading all claims and passages at once missed the changed role, and the following run corrected that case. Retrieval also reserves a quarter of each result window for the newest dated near-top matches, so a 2025 announcement and a 2026 company page reach the model together instead of the announcement's many copies filling the window. No entity, role or fact is named in code; the same rule handles a leadership change, a network count and a pricing exception.

AI-directed instructions are removed during ingestion, including adjacent directives and editorial guidance in explicitly AI-addressed documents. Only allowlisted provenance metadata reaches the model; removed text is not reintroduced through a sanitation audit. Code validates action schemas, citation IDs, source-backed dates and numeric occurrences. A separate metered model review checks semantic support, scope and retrieved counterevidence before publication. This layered boundary is more than prompt formatting, but it is not a universal prompt-injection or truth detector: unknown phrasings and model errors remain possible. The first full evaluation exposed an unsupported universal tip claim; a general counterevidence review alone did not remove it in the next two runs, and only the focused scope comparison with a subject-specific exception search did. Model-based controls therefore need the retrieval step that puts the limiting passage in front of them; without it they approve what they are shown.

“No reliable answer” means an explicit evidence-based abstention. Provider failure, invalid output and exhausted research limits are errors. An unknown cost is null, not zero. A low or high Trust Score cannot bypass failed gates. Partial answers are allowed but still fail evaluation when they omit a required conclusion. This makes the implementation conservative and occasionally less useful; the evaluation counts those failures.

## Updating and live changes

Forced-source, all-source and due-source refresh commands use a durable job and a staging database. Collection and new embeddings finish before text, vectors and corpus version activate in one transaction. Failed jobs leave the serving corpus intact and can resume cached work. The legacy `/api/refresh` endpoint requires a private token. The separate Updates screen now intentionally exposes public demo actions through JSON-only routes with browser origin checks; it does not ask for an operator token. It starts all enabled sources, retains batch progress across reloads, and offers failed-source retries and collapsed advanced scheduling controls. One real targeted refresh was exercised in addition to offline failure/activation fixtures. New pages on supported sites need no prompt edit. New domains require source configuration and provenance; new formats require a small adapter and test. The system does not rewrite its own code or silently promote a source's claimed authority.

The application now includes an operator-controlled scheduler, off by default, with per-source intervals and priorities. Manual and scheduled work share one durable queue. Incremental YouTube discovery skips known IDs before Soniox and retains cached processing after failure; bounded discovery and ambiguous candidates remain explicit limits. This extension was verified locally, without changing the hosted corpus or rerunning paid evaluation; see [Updates](docs/UPDATES.md). Completed staging databases are retained for inspection and need an operational retention policy. Ambiguous video candidates still require review before paid processing. These are explicit operational limits rather than a claim of unattended production readiness.

## Measured quality, cost and limits

The final agent passed 19/20 (95%) with no case containing an unsupported assertion, versus 11/20 (55%) for the one-pass baseline. The remaining failure (E05) is an incomplete two-year trajectory that covers the 2025 shift but omits the earlier retail baseline and the 2026 products. The three earlier complete runs are retained: 15/20, 14/20 and 16/20 with one, two and one unsupported-fact cases. The step from 16/20 to 19/20 came from the focused currentness and scope reviews: the 16/20 run still presented the June 2025 announcement as the current chief executive and an unconditional tip rule, both of which the following run corrected by citing the newer company page and the no-tip path. The baseline lost two cases to its single answer turn: a draft rejected by the same reviews has no repair step there, so the run ends as an error. The final [EVAL.md](EVAL.md) contains every question, reference, actual answer and verdict for the fixed set of twenty, including five negatives. It separately counts cases with invented facts and preserves failed/diagnostic runs. The comparison baseline gets six initial passages, one answer turn and the same safety gates, without research tools. A protocol error in its first attempt was detected and that incomplete run was excluded from quality comparison while retaining its costs. Independent review is performed by a separate coding agent against the frozen evidence; it is not presented as human-certified ground truth.

Including the deployment smoke queries, four full agent evaluations, four baseline evaluations and the diagnostic questions, the rebuild recorded $4.616122 in known usage-priced charges and 22 calls with unknown cost (six Soniox jobs, six pre-deployment failures and ten attempts cancelled by a stopped request). Indexing used 2,134,172 measured input tokens for $0.042683 known; multiplying the observed build by 50 gives 106,708,600 tokens and $2.134172, excluding unresolved charges. [COST.md](COST.md) and the ledger retain dated measurement snapshots, per-query costs, retries and explicit assumptions; later additions are reported separately. Soniox billing was not returned by its API, so its duration-based forecast is separated from actual known charges. The HTTPS smoke question took 29.1 seconds and cost $0.039480, returning three dated sources. The final agent evaluation averaged $0.042121 per query (median latency 22.5s), versus $0.012177 for the baseline; the counterevidence searches and focused reviews added roughly $0.008 per question over the 16/20 run. Existing subscription usage and server rental are outside provider-token totals. Query/evaluation timings and CPU/RSS observations are attached to each full run. Exact vector scanning is simple to explain but already memory-heavy; 50× corpus growth would require an approximate vector index and a new performance measurement rather than a claim of unchanged latency.

The [MCP comparison](docs/MCP_COMPARISON.md) is pinned to inspected official source code and now includes an actual captured-tool-context twenty-question measurement. Everstake's own operational tools are the better source for live APY, supported chains and uptime. This system adds historical, multi-source evidence and measurement, at the cost of crawling, model latency and retrieval mistakes. It does not replace those authoritative live services.

## Deliberate cuts and a month-long next version

The priority was a demonstrable, measured system within the assignment's small human-effort budget. We did not process the entire video inventory, bypass blocked social sites, implement OCR/PDF/audio visual grounding, expose a full historical-revision browser, or build distributed ingestion infrastructure. The original local prototypes were preserved without rewriting their timestamps. Human effort estimates and autonomous execution are distinguished in [TIME.md](docs/TIME.md); no complete stopwatch total is claimed.

With one month, I would first expand blind, held-out evaluation and manually calibrate support/abstention decisions, then improve date/condition retrieval and reviewer adjudication of video identity. Operational priorities would be invoice reconciliation, source freshness SLAs, staging retention, scheduled incremental jobs and a vector index appropriate to the measured scale. Part B in [PROCESS.md](PROCESS.md) deliberately keeps permissions, scheduling, completeness checks and final publication outside the agent.

## Follow-up: quantity scope and visible claim dates (2026-09-13, local)

A user question exposed a presentation and comparison gap: per-claim dates were omitted from answer text, while the newest document date labelled the whole answer. The active-network and lifetime-network figures were individually sourced but could imply an unsupported decline. Claims now preserve a reviewed temporal scope plus date basis/source; API and UI show each labelled date, publication remains visible, and a cumulative label distinguishes lifetime coverage from a previous simultaneous count. Metadata cannot establish a fact's effective date. Same-subject counterevidence is retained even without a newer timestamp, and a whole-answer scope review can reject misleading relationships after individual claims pass. Provider thinking/output limits and bounded repair attempts were adjusted after recorded truncation failures.

The [audit and diagnostic receipts](docs/research/network-scope-and-dates/README.md) preserve exploratory failures and the final successful Ukrainian query: 35+ active networks, 130+ cumulative coverage, separate dated citations. The final query cost $0.06479272. Offline checks passed 142 tests plus typechecking; desktop/mobile replay verified rendering and citation navigation. These are local changes and diagnostic measurements, not a deployment or a new 20-question EVAL result. Additional diagnostic costs are reported separately in the audit rather than silently added to the prior published aggregate.

The official MCP server successfully returned all ten read-tool probes; its integration-request write tool was not invoked. Nine generic outputs became a frozen context for twenty calls to the same configured answer model, without corpus retrieval, reference answers or grading rubrics. Two independent rubric/source reviews of `mcp-8bcd1ef1` agree on **7/20 (35%), 13 failures and 0 invented-fact cases**. Three responses answered and seventeen abstained; safe refusals on missing positive coverage still fail those tasks. The genuine MCP 130+ network claim fails the frozen reference's active/lifetime-scope requirement without becoming an invented number. [Original answers](artifacts/evaluation/mcp-2026-09-13.json), [grading](artifacts/mcp/grades-2026-09-13.json) and [methodology](docs/MCP_COMPARISON.md) remain separate.

This run adds **$0.23630625 in measured usage-priced generation cost**, with no unknown charges; it is a separate measurement, not a refreshed all-time ledger total. The earlier 19/20 agent result is not rerun or replaced. The comparison uses different evidence and verification budgets, and the MCP capture cannot prove the performance of an autonomous MCP client. Observation times are not fact-effective dates, and correct citation IDs alone do not establish factual truth.

The current interface adds searchable paginated Corpus browsing, dense Costs breakdowns with non-overlapping root-operation receipts, clearer Evaluation comparison, and token-free Updates progress. A repeated full-pass request preserves completed members while adding missing enabled sources; viewing an ongoing update only fetches status. Browser origin checks mitigate cross-site writes but are not user authentication: update actions are deliberately public demo functionality. No deployment or live-host verification of this redesign is claimed by these local code and benchmark changes.
