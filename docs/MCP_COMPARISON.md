# Comparison with Everstake MCP

This comparison is based on source inspection of Everstake MCP at commit [`68f5f5f`](https://github.com/everstake/mcp/tree/68f5f5f02b15a666849438971a65d5923a96e5ee), not on a head-to-head answer-quality benchmark: that server registers seven read-only tools backed by curated static text, three dynamic tools for uptime, supported chains, and staking calculations, and one tool that submits an integration request ([tool registration](https://github.com/everstake/mcp/blob/68f5f5f02b15a666849438971a65d5923a96e5ee/internal/server/mcp/server.go#L30-L53), [static tool content](https://github.com/everstake/mcp/blob/68f5f5f02b15a666849438971a65d5923a96e5ee/tools.yaml#L9-L78), [dynamic and write handlers](https://github.com/everstake/mcp/blob/68f5f5f02b15a666849438971a65d5923a96e5ee/internal/server/mcp/dashboard.go#L38-L138)). Everstake MCP is the better fit for current operational values such as APY, chain availability, uptime, and calculator output, and for requesting an integration, because those capabilities query Everstake's service directly without this project's server-side crawl and index. This assistant is better suited to the assignment's historical and research questions because it preserves dated public snapshots from multiple publishers, exposes specific citations, separates publication from observation time, groups duplicates, retains revisions, and applies measured abstention and verification gates. Its disadvantages are crawl and index latency, model and embedding cost during search and answering, possible retrieval misses, incomplete handling of undated or JavaScript-only pages, and weaker freshness for changing operational facts. The inspected MCP tool surface does not expose corpus-wide history, duplicate groups, per-claim dated provenance, or this project's evaluation receipts, while this project does not replace MCP's authoritative live service calls; the two systems serve different evidence horizons.
