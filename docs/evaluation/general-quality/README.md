# Перевірка складних відповідей

> This is a saved investigation. [Previous evaluation report](EVAL-previous.md), [runtime snapshots](runtime-snapshots.json) and [diagnostic costs](task-costs.json) preserve its evidence. Use the root [EVAL.md](../../../EVAL.md) for the published result; the original investigation text follows.

Працюємо над загальними правилами пошуку й перевірки, без готових відповідей на окремі питання в коді.

## Що було не так

- Пошук знаходив потрібну статтю, але не обов’язково потрібний абзац. Читання повертало наступні чотири уривки без пошуку всередині документа.
- Перевірка могла схвалити два окремі факти, не помітивши, що разом вони суперечать один одному.
- Історичний факт міг пройти як відповідь на запит про поточний стан.
- Загальне правило протоколу іноді перетворювалося на твердження про конкретний гаманець, якого система не перевіряла.
- Українські категоричні формулювання не запускали пошук винятків. Десяткова кома розбивала число на частини.
- Пошкоджена відповідь додаткового перевіряльника раніше могла непомітно залишити схвалення чинним.

## Що змінили

Можна шукати потрібний аспект у всіх проіндексованих уривках відомого документа. Читання показує, чи є продовження. Додаткова перевірка шукає докази і за самим запитанням, а не лише за чернеткою відповіді.

Перевіряємо відповідь цілком, включно з короткими відповідями без чисел. Перевіряльник окремо називає непідтверджені припущення: наприклад, вигадане пояснення розбіжності джерел. Якщо пояснення немає, система має сказати про невизначеність. Для нечіткого результату перевірки є одна оплачена повторна спроба; подальший збій показується як помилка, а не як успішна перевірка.

Це зменшує ризик помилок, але не доводить безпомилковість: зміст досі перевіряє модель. Точність оцінюємо за зовнішнім переглядом відповідей, а не за її власним схваленням.

## Які питання залишили

Основний набір `core-v2` має 20 питань і п’ять негативних випадків. Збережено 19 попередніх питань, зокрема CEO, суперечливі цифри, порівняння джерел та зміни з часом. Просте питання про рік заснування E03 замінено на E21: схвалення зміни, її запуск, прогноз винагород і позиція учасника голосування.

Окремий набір `scenarios-v1` має сім життєвих ситуацій: дозволи REStake, зупинка автоматизації, витрати Polygon, нагороди NEAR, повторна зміна валідатора NLS, старий і новий внески SOL та суперечливі строки виведення SUI. Він не змінює знаменник основного evaluation.

Попередні результати залишаються історичними. Заміна питання змінює склад тесту: відсотки різних наборів не є прямим порівнянням якості.

Запуск: `npm run cli -- eval agent` для основних питань; `npm run cli -- eval agent --scenarios` для додаткових. Прогін зберігає справжні відповіді й витрати, але до окремої оцінки результат залишається неперевіреним. Відкриття вкладки Evaluation не запускає платних запитів.
