# Як читати й змінювати цей код

Цей маршрут готує до §§9–10 завдання: пояснити рішення й виконати зміну наживо. Він не замінює читання реалізації. Короткий сценарій показу — [DEFENCE.md](DEFENCE.md), вимоги — [оригінальне завдання](TEST_ASSIGNMENT_EN.md).

## Слова, які зустрінуться в папках

| У коді | Простими словами | Де подивитися приклад |

Не потрібно вивчати всі терміни напам’ять. Відкрий README конкретної папки, знайди її вхідний файл і пройди один сценарій до результату.

## 1. Спочатку розрізни чотири види файлів

| Де | Для чого | Що відбувається після зміни |
|---|---|---|
| `src/`, `web/` | Код сервера й браузера | Потрібні відповідні перевірки; frontend ще треба зібрати |
| `assistant/config/`, `assistant/agents/` | Джерела, моделі, обмеження та визначення агента | Впливає на нові запуски; конфігурація має пройти валідацію |
| `assistant/prompts/`, `assistant/skills/` | Інструкції моделі та правила роботи з доказами | Може змінити якість; unit-тест не замінює нового evaluation |
| `eval/`, `artifacts/`, кореневі звіти | Питання, збережені результати й пояснення | Правка документа не змінює вже виміряну поведінку |

`src/services/` — функціональні модулі **одного процесу**, а не окремі сервери. `src/workflows/` з’єднує модулі в довші операції. `deploy/` описує запуск контейнера. `scripts/` містить допоміжні команди оператора. `docs/plan/` пояснює історичний задум; актуальну поведінку перевіряй у коді й тестах.

[config.ts](../src/config.ts) має `readPolicy()`, `readResearcher()` і `readSources()` із перевіркою Zod; [provider-config.ts](../src/providers/provider-config.ts) завантажує моделі через `loadModelsConfig()`. `maxSteps` має одного власника — визначення агента. YAML підтримує коментарі `#`. TypeScript підтримує `//` та `/* ... */`. Коментар пояснює причину, одиниці виміру або інваріант. Наприклад, навіщо зберігати процитований уривок під час ремонту відповіді, а не те, що наступний рядок створює масив.

## 2. Як запускається застосунок

Читай [main.ts](../src/main.ts), потім [application.ts](../src/application.ts), [api.ts](../src/api.ts) та [contracts.ts](../src/contracts.ts).

`main.ts` відкриває SQLite й запускає HTTP-сервер. `application.ts` з’єднує базу, провайдерів, пошук, відповіді, витрати й оновлення. Тут залежності передаються функціям: тест може замінити реальну модель на керований об’єкт із тим самим інтерфейсом. `api.ts` перевіряє запит і переводить виклики функцій у HTTP-відповіді. [cli.ts](../src/cli.ts) надає команди для тих самих основних сценаріїв.

`interface` описує форму даних для TypeScript, але не перевіряє JSON під час виконання. Zod-схема виконує таку перевірку. `async` повертає Promise; `await` чекає результат операції. `AbortSignal` повідомляє, що клієнт припинив запит, щоб зупинити подальшу роботу.

## 3. Як текст стає доказом

Почни з [build-corpus.ts](../src/workflows/build-corpus.ts) і [crawl-source.ts](../src/services/crawler/crawl-source.ts). Краулер бере дозволені джерела з `assistant/config/sources.yaml`, читає robots, обмежує запити й записує причини виключення. Виявлене зовнішнє посилання ще не є дозволом його завантажувати.

[extract.ts](../src/services/crawler/extract.ts) дістає зміст і metadata з HTML. [sanitize-document.ts](../src/services/evidence/sanitize-document.ts) прибирає розпізнані інструкції, адресовані AI, до hashing, розбиття та індексації. Лишається кількість вилучень і назви правил, а не шкідливий текст у контексті моделі. Це набір конкретних правил, а не доказ захисту від усіх можливих формулювань; новий обхід потребує fixture й перевірки всього шляху.

[deduplicate.ts](../src/services/indexer/deduplicate.ts) знаходить однакові та близькі тексти. [chunk.ts](../src/services/indexer/chunk.ts) ділить документ на пошукові уривки. Exact-копія не повинна додавати незалежний «голос». Near-копії можуть містити суттєві відмінності, тому групування не означає їх безумовного видалення.

Для відео [pipeline.ts](../src/services/youtube/pipeline.ts) з’єднує транскрипцію та перевірку мовців. [evidence-turns.ts](../src/services/youtube/evidence-turns.ts) відбирає придатні репліки: запитання ведучого не стає твердженням компанії. Невпевнене встановлення особи обмежує індексацію; таймкод і роль стосуються запису, а не автоматично сьогоднішнього дня.

## 4. Навіщо SQLite, FTS і embeddings

Відкрий [schema.sql](../src/storage/schema.sql) поруч із [database.ts](../src/storage/database.ts).

| Таблиця | Що зберігає |
|---|---|
| `documents` | URL, hash, активність і знімок документа з metadata |
| `chunks`, `chunks_fts` | Уривки та повнотекстовий індекс для пошуку слів |
| `embeddings` | Вектор уривка разом з ідентифікатором моделі |
| `runs`, `api_calls` | Запуски та окремі спроби звернення до провайдера |
| `answers`, `evaluations` | Збережені відповіді й результати перевірок |
| `settings`, `crawl_events`, `youtube_jobs` | Стан, причини виключення й відеоробота |

FTS шукає слова локально. Embedding представляє зміст числовим вектором і допомагає знайти перефразоване питання. [hybrid-search.ts](../src/services/search/hybrid-search.ts) поєднує сигнали, враховує групи дублікатів і датовані матеріали. Схожість допомагає знайти кандидата, але не доводить його актуальність.

Заміна embedding-моделі вимагає сумісних векторів документів: не можна порівнювати вектор нового питання з індексом іншої моделі. Перебудова embeddings може коштувати грошей. Транзакція SQLite дозволяє застосувати пов’язану зміну цілком або не застосувати її; вона не робить віддалений API-запит частиною локальної транзакції.

## 5. Один запит від питання до відповіді

Відкрий [answer-question.ts](../src/services/answer/answer-question.ts). Основний порядок: завантажити правила → знайти перші уривки → запитати дію моделі → перевірити її формат → виконати дозволений інструмент → перевірити чернетку → повернути результат або запросити обмежене виправлення.

[research-action.ts](../src/services/answer/research-action.ts) перевіряє структуру дії; [research-evidence.ts](../src/services/answer/research-evidence.ts) керує вікном доказів і походженням результату обчислення. Модель може запропонувати `search`, `read`, `calculate` або `answer`. Це структуровані дані, а не довільний JavaScript чи shell. `search` працює зі зібраним корпусом. [readDocument](../src/services/search/search-corpus.ts) повертає частину збереженого документа, зокрема уривки навколо потрібного терміна. [calculate.ts](../src/services/answer/calculate.ts) виконує дозволену арифметику й перевіряє походження операндів.

**Реєстр доказів** — відповідність `passage ID → EvidencePassage` для поточного запиту. Він дає коду відповідь на питання: «Чи справді цей уривок повернув інструмент?». URL, який модель просто придумала, не стає доказом. Вікно уривків обмежене; під час ремонту чернетки важливо зберегти вже процитовані докази. Реєстр підтверджує походження, а не істинність твердження.

## 6. Де перевіряє код, а де модель

[verify-answer.ts](../src/services/answer/verify-answer.ts) перевіряє існування citations, наявність чисел у процитованих доказах і підтримку дати. Наявність `1 000 000` та `0.0005` окремо не доводить їхню рівність. [verify-claims.ts](../src/services/answer/verify-claims.ts) просить модель перевірити зміст, одиниці, межі твердження й відповідь загалом.

[counterevidence.ts](../src/services/answer/counterevidence.ts) шукає новіші докази та винятки: новий документ може спростувати стару посаду, а окрема тарифна умова — обмежити слово «завжди». Семантичний перевіряльник теж може помилитися; зелений check не є математичним доказом істини.

[score-evidence.ts](../src/services/trust/score-evidence.ts) пояснює Trust Score. Це евристика довіри до доказів, не ймовірність правильності й не спосіб обійти провалені перевірки.

`no_reliable_answer` означає, що доступних доказів недостатньо. Помилка провайдера чи неправильний формат його відповіді — технічний збій, який не доводить відсутності факту. Не перетворюй винятки на «не знаю», щоб зробити інтерфейс зеленим.

## 7. Чотири різні дати

[claim-date.ts](../src/services/answer/claim-date.ts) зв’язує дату твердження з доказом і формує чесний підпис:

- `effective` — дата чинності факту, яку треба підтвердити змістом;
- `published` — публікація джерела, для відео дата завантаження;
- `updated` — оновлення джерела;
- `observed` — коли ми перевірили сторінку (`fetchedAt`).

Сторінка, завантажена сьогодні, може описувати подію 2025 року. Дата в тексті є технічною підставою перевірки, але її застосовність до конкретного факту оцінюється окремо. Для різночасових тверджень не призначаємо всій відповіді дату найновішої цитати.

`temporalScope: cumulative` позначає накопичений показник. «130+ мереж за весь час» і «35+ активних» не доводять падіння одночасної кількості зі 130 до 35.

## 8. Як браузер показує роботу

[web/app.ts](../web/app.ts) керує екраном; [read-run-stream.ts](../web/transport/read-run-stream.ts) читає SSE. Сервер надсилає події пошуку, перевірки та фінальної відповіді одним відкритим HTTP-потоком. Мережевий фрагмент не обов’язково містить повну SSE-подію, тому parser накопичує дані до межі повідомлення.

Це журнал дій застосунку, не приховані міркування моделі. [run-state.ts](../web/run-state.ts) розрізняє очікування, завершення, помилку й зупинку. Після розриву потоку клієнт не повинен непомітно створювати новий платний запит. Компоненти `web/features/` показують відповіді, джерела, витрати й перевірки. Тека `web/features/` має шість папок за сторінками інтерфейсу. Форма, прогрес, відповідь і цитати зібрані в `ask/`: для тексту помилки відкрий `request-error.ts`, для карток джерел — `source-cards.ts`.

## 9. Витрати й оновлення корпусу

[model-client.ts](../src/providers/model-client.ts) готує запит для конкретного провайдера й читає його відповідь. [metered-request.ts](../src/providers/metered-request.ts) перевіряє бюджет, записує спробу до API-виклику, обліковує результат і керує повторними спробами. Скасування під час паузи не починає наступний запит; сама пауза завершується за таймером. [receipt.ts](../src/services/measurements/receipt.ts) збирає її витрати разом із дочірніми викликами без повторного рахунку. `null` означає невідомо; резерв бюджету є прогнозом. Датований тариф і usage дозволяють відтворити суму. [COST українською](../submission_ukr/COST.md) відокремлює історичний журнал від пізніших прогонів.

[updates/controller.ts](../src/services/updates/controller.ts) керує чергою й прогресом. [staged-refresh.ts](../src/workflows/staged-refresh.ts) готує окремий staging-корпус, збирає документи й embeddings, перевіряє його та лише потім активує. [refresh-lease.ts](../src/workflows/refresh-lease.ts) контролює власника оновлення; [corpus-activation.ts](../src/workflows/corpus-activation.ts) перевіряє стан і виконує активацію. Lease із терміном дії не дозволяє старому процесу перезаписати роботу нового власника. Зміни активної бази після створення staging теж треба врахувати.

Невдалий збір не замінює чинний корпус частковими даними. Водночас уже виконані платні виклики не зникають із витрат. Докладний контракт — [UPDATES.md](UPDATES.md).

## 10. Репетиція зміни наживо

Перед кожною правкою назви очікувану зміну й тест, який її покаже. Виконуй із кореня репозиторію.

| Запит інтерв’юера | Де змінювати | Як довести результат |
|---|---|---|
| Менше дослідницьких кроків | `assistant/agents/researcher.yaml`, `maxSteps` | Тест answer loop із модельною заглушкою; показати зупинку за лімітом |
| Інший розмір вікна доказів | `assistant/config/policy.yaml`, `maxEvidence` | Перевірити межу й збереження потрібних citations під час ремонту |
| Додаткове джерело | `assistant/config/sources.yaml` | Спершу валідація конфігурації; потім цільовий refresh і його виключення |
| Нова форма AI-інструкції | `sanitize-document.ts` та сусідній тест | Шкідлива фраза видаляється, звичайна фактична фраза зберігається |
| Неправильна дата у відповіді | `claim-date.ts`, `claim-date.test.ts` | Джерело без effective date не отримує вигаданої дати чинності |
| Збій оновлення після crawl | `staged-refresh.test.ts` | Активний корпус зберігається, job має помилку, витрати видимі |

Безкоштовна перевірка локальних fixtures: `npm run typecheck`, потрібний тест через `npx tsx --test src/services/answer/claim-date.test.ts`, загальний `npm test`; після frontend-правок — `npm run build:web`. Команда `npm run cli -- refresh <source-id>` виконує реальний збір і може викликати платні embeddings. Новий evaluation теж є окремим вимірюванням із витратами.

Для незрозумілого рядка дай п’ять відповідей: звідки дані, який тип, що змінюється, що буде при помилці, який тест це показує. Якщо хоча б одна невідома, пройди виклик до реалізації, а не завчай опис файла.

## 11. Де шукати окремий крок після другого проходу

| Потрібно пояснити | Почни звідси |
|---|---|
| Як CLI вибирає команду | `src/cli.ts`: `runCommand`, `crawlSelectedSources`, `indexCollectedDocuments` |
| Як оновлюється одне джерело | `src/application.ts`: `executeSourceUpdate` |
| Як читаються дати сторінки | `src/services/crawler/extract.ts`: `readPageDates` |

| Як збережений transcript приводиться до поточного формату | `src/services/youtube/transcribe-video.ts`: `refreshSavedTurns` |

Функції названі за кроками роботи; пояснення біля перевірок описують причину обмеження. Починай із основної функції файла й переходь до допоміжної лише тоді, коли треба розібрати цей крок.
