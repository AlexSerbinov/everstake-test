# Звіт за 2026-09-12

## Що зроблено

**Агентний шар замість «один пошук → один промпт».** У `claude-work` тепер є модель-оркестратор (`src/ask/agent.ts`) із шістьма інструментами: пошук по корпусу, історія фактів із ledger, читання документа, живий fetch дозволених сторінок (allow-list, robots, кеш 1 год), живі цифри з MCP Everstake (тільки APY/uptime, завжди з позначкою «live»), `finish`. Правила вибору інструментів лежать у `prompts/agent.md`, опис для людей у `agents/orchestrator.md`. Максимум 6 викликів, після чого примусовий `finish`. Усі гейти лишились у коді.

**Видимий пайплайн.** `POST /ask/stream` віддає SSE-події (stage, tool_call, tool_result, note, final). Новий UI показує їх наживо: план → ledger → пошук → live-сторінка → відповідь → перевірка, з часом кожного кроку і розгортанням результатів. Перший екран: одне поле питання. Решта (таймлайн фактів, корпус, інструкції для AI, eval, налаштування) за меню Explore. Дві теми, 0 порушень WCAG A/AA.

**Gate 3: заземлення чисел.** Кожен числівник у відповіді має бути в тексті, який реально повернули інструменти (з урахуванням «1.6 million» = «1,600,000»). Відповіді з незаземленим числом не показуються.

**Adversarial-тести.** `eval/adversarial.yaml`: 8 інʼєкцій у питанні, 6 підставних документів з канарками (індексуються в копію бази штатним шляхом), 6 хибних передумов. Вердикти ставить код, не суддя. Результат: 16 PASS, 4 WARN (система спростувала хибну передумову з цитатами замість голої відмови), 0 FAIL, 0 канарок у відповідях.

**Eval на агентному шляху.** 20 питань: strict 80% (було 70%), lenient 95%, 0 хибних, 0 хибних відмов, 1 «галюцинація» за суддею на n03 (агент знайшов реальні задокументовані ставки і спростував передумову; нічого не вигадано, залишено як провал чесно). Вартість запиту $0.048, латентність ~10 с.

**Дослідження** (`docs/research/`): актуальність даних (гібрид: індекс + вузький live fetch + MCP для живих цифр; інкрементальний re-crawl трьома ситами), масштаб і довіра (6 000 дзвінків через Soniox ≈ $300, provenance через sha256 і WORM, підписаний audit log, модель не рахує числа), adversarial-план, внутрішня система для операційного директора (шлюз → конектори з ACL → службові записки → звіти → детектори; що НЕ агент), самозвітність проєкту.

**Друга версія (Codex, GPT-5.6)** отримала той самий список цілей і розвиває `codex-work/` самостійно.

## Рішення

- Живі цифри (APY, uptime) не індексуються, беруться з MCP Everstake у момент запиту з позначкою. Історія і факти про компанію — тільки з корпусу.
- Undated first-party сторінки = «живі станом на дату краулу»; датований анонс, старіший за краул, не перебиває їх.
- Провайдерська помилка ніколи не видається за «не знаю» (окремий gate `model_error`).
