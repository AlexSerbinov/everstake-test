# Time spent — measured, not estimated

The assignment expects 6–8 hours of effort (§2) and asks for a git log with real timestamps (§8.5). This file states how much of the author's own time went in, how the number was produced, and why it differs from the span of the git log.

**Hands-on time so far: 3.3 h** (as of 2026-09-12 18:04, Europe/Madrid). Part B is not written yet; the assignment budgets it separately (~1 h).

## Method

The work is spread over several days, and much of the elapsed time was agents running on a brief while the author was away: Claude Code sessions, a Codex run on the second implementation, an overnight evaluation pass. Commit timestamps therefore mark when an agent finished, not when a person worked — ten commits within one minute at 20:39 on 2026-09-11 are one agent recording a finished run.

What is measured is presence at the task, from two independent logs:

1. **Prompts to Claude Code** — the timestamp of every message the author typed or dictated in this project's sessions. Messages generated by the tool itself (background-task notifications and the like) are excluded; they are agent activity, not the author's.
2. **Voice dictations** — the dictation app records a timestamp for every voice prompt, including questions put to the deployed system in the browser, which never appear in a Claude Code transcript. Only dictations within this assignment's time windows are kept, since the app has no project tag.

**Rule.** Events less than 10 minutes apart form one block; a block lasts from its first to its last event; a block with a single event counts 5 minutes. Time with no events — reading, thinking, an agent working alone — is not counted.

Reproduce: `python3 docs/time/count.py` over `docs/time/events.csv` (timestamps only; no prompt text is published). It prints the raw blocks; the table below groups them into working sessions. `docs/time/extract-local.py` is the script that built the CSV from the two local sources.
